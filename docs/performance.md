# Проверка производительности 0.2.3

Измерено 10 ноября 2026 на Windows, Direct3D, AMD Radeon(TM) Graphics (495 MB VRAM по данным
Skiko), окно 1280×880. Оба прогона через Gradle использовали один JBR 21; дополнительно проверен
собранный образ с комплектным Java 21.0.7. Исходный код — `f1c0390`: в отдельную рабочую копию
добавлены только тот же стенд и 600 вымышленных серверов.

Счётчик оборачивает реальный `SkikoRenderDelegate.onRender` и не запрашивает дополнительные кадры.
На сценарий отведено 5 секунд после прогрева. Для воспроизводимости стенд использует политику
активного окна независимо от фокуса чата. Реальный VPN не запускается.

| Сценарий | Исходная, FPS | 0.2.3 через Gradle, FPS | Готовый образ, FPS | p99 готового образа, мс |
|---|---:|---:|---:|---:|
| Планета | 24.6 | 58.4 | 55.1 | 24.3 |
| Волны | 23.3 | 60.0 | 59.9 | 20.2 |
| 600 серверов, без прокрутки | 18.0 | 60.0 | 60.0 | 18.4 |
| 600 серверов, 1200 px/s | 13.9 | 53.8 | 56.4 | 50.7 |
| 600 серверов, 3600 px/s | 13.0 | 54.3 | 59.5 | 30.6 |
| Настройки, фон неподвижен | 30.0 | 59.9 | 59.9 | 18.1 |
| Окно скрыто | 0.0 | 0.0 | 0.0 | 0.0 |

Нулевой FPS скрытого окна означает отсутствие отрисовок. Это короткие локальные замеры
с вымышленными данными: FPS на других устройствах, при другом масштабе Windows или с реальным
сетевым трафиком может отличаться. Это не проверка работоспособности реального туннеля.

Слои сцены и матовое стекло готовятся на рабочем потоке и публикуются одним завершённым кадром;
панели используют готовое изображение. Неподвижный фон не перестраивается при движении содержимого.
Рисование не меняет наблюдаемый им счётчик. Содержимое панелей записывается отдельно, непрерывные
анимации останавливаются в скрытом и свёрнутом окне. Список остаётся ленивым, поиск не повторяет
фильтрацию при каждом ответе пинга, результаты пинга записываются пакетами по 200 мс.

Общая загрузка CPU на активном окне может быть выше из-за большего числа кадров. Речь о плавности
и меньшей работе на кадр, а не об обещании снижения энергопотребления. В исходных TSV значение
`cpu_core_percent=100` означает один полностью занятый логический процессор.

Проверки: 401 JVM-тест, включая Skia-отрисовку неподвижного фона, изменение палитры и размера,
поиск и выбор последнего из 600 серверов, автоподключение, получение и проверку обновлений,
кнопки загрузки, отмены и перезапуска; тесты Go-службы; сборка Windows-образа и Inno Setup.
Полная установка обновления поверх рабочей службы и реальный туннель не запускались.
Штатный HTTPS-транспорт собранного приложения также проверен на живом GitHub: метаданные
выпусков и файл контрольной суммы получены, выбран опубликованный Windows-выпуск 0.2.2.

Обновления повторяют сценарий
[Masaki](https://github.com/GXUser7/Masaki/blob/v0.7.0/src/main/updater.ts): фоновая проверка
и загрузка, установка при выходе либо по кнопке перезапуска. В Yumi установщик также обновляет
службу и запрашивает права Windows.

Повторить: `./gradlew.bat :desktop:run --args="--ui-benchmark"`. Результат —
`desktop/.local/performance/benchmark.tsv`. Собранный `Yumi.exe --ui-benchmark` пишет
`.local/performance/benchmark.tsv` относительно рабочего каталога. Все тестовые данные
изолированы от `%LOCALAPPDATA%/YumiDesktop`.
