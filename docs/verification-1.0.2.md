# Проверка изменений 1.0.2

Мобильный репозиторий обновлён до `f815bd5` (2.1.8). Desktop использует тот же разбор документов
Happ и политику выбора `NodeGroup.pick`: cost/fastest, порядок участников и предел задержки.
Тест пинга групп перенесён из mobile с сохранением отмены сетевых операций desktop.

## Подключение, поиск и Happ

- При подключении сразу измеряется активный туннель. Его задержка хранится отдельно от
  обновляемого списка подписки и не теряется при смене ID или удалении строки.
- Поиск хранится в модели и сохраняется между страницами. «Пинг» проверяет только результаты;
  изменение поиска отменяет старую проверку. Отдельное действие трея проверяет весь список.
- Служба получает все маршруты группы вместо принудительного первого. Она проверяет HTTPS
  через каждого участника с настоящей авторизацией и выбирает по политике провайдера.
- Новые соединения используют выбранный маршрут, открытые сохраняют прежний.
  При отказе группа проверяется заново; плановое сравнение участников — раз в две минуты.
- В интерфейс возвращён признак `Auto ×N`.

Настоящая подписка проверена отдельно от рабочего профиля: **542 строки, 25 групп, 113 участников**.
Пинг получен для всех 25 групп; закреплённое ядро приняло все 113 конфигураций.
В одной реальной группе выполнен проверенный HTTPS-запрос через выбранного участника.
Временные приватные запросы из игнорируемой `.local/live-verification` удалены после проверки;
сохранён только отчёт с количествами.
Рабочий профиль и действующий туннель не изменялись.

Реальные проверки `LiveSubscriptionTest` и `TestLiveProviderGroupWhenExplicitlyRequested`
запускаются явно; обычный CI пропускает их без учётных данных. Синтетический интеграционный тест
также проверяет второй маршрут, когда первый принимает TCP, но отклоняет авторизацию,
и передачу данных через этот маршрут.

## Закрытие пунктов 5–9 аудита 1.0.0

- Первое явное подключение Unix устанавливает службу с запросом прав и ждёт её ответа.
  Фоновый опрос не запрашивает права, отмена не вызывает повторного запроса.
  Бинарник службы копируется в защищённый каталог; обновление приложения перезапускает helper.
- PF использует свой anchor и enable-token, сохраняет системные правила и чужие сеансы PF.
  Закрытие старого фильтра сохраняет новый. Восстановление учитывает перезагрузку ОС
  и очищает старый anchor 1.0.x. При включении закрываются прежние PF-состояния, при горячей замене — сохраняются.
- nftables не разрешает обходной исходящий трафик лишь из-за `established`.
  Исправлены DHCPv6/NDP; запуск службы очищает только её оставшиеся таблицы.
- DNS записывается до изменения. Пустые DNS macOS восстанавливаются через `Empty`.
  Частичное применение откатывается; неудавшиеся восстановления остаются на диске для повтора.
  Supervisor восстанавливает DNS после смерти worker и при запуске. resolved получает `~.`
  и полностью очищается через `revert`; поддержан старый файловый backup Linux.
- Геолокация сохраняет обе Windows-политики с типами/значениями/отсутствием, состояние
  GeoClue/launchd и исходную таймзону. Намерение изменения часов записывается до команды ОС.
  Применение и восстановление сериализованы; ошибка не уничтожает снимок. В Windows новые
  снимки находятся в защищённом подкаталоге с миграцией старого пути.
  У снимков 1.0.x отсутствующие первоначальные значения достоверно восстановить невозможно;
  существующая политика в таком случае сохраняется.
- IPC Unix имеет общий срок ожидания, завершает неполные записи и закрывает сокет при отмене.
  Пути для привилегированного shell экранируются буквально.

## Проверки и границы

Локальный полный JVM-прогон Windows: 462 теста, 0 ошибок. Четыре проверки Unix-сокетов
пропускаются на Windows, реальный провайдер проверен отдельным явным прогоном.
Тесты Go и `go vet` успешны на Windows. Linux-сборки тестов службы и firewall также выполнены в WSL.

Workflow дополнен race detector на Linux/macOS, проверкой nftables внутри отдельного
network namespace и системным PF parser без загрузки правил, помимо пакетов и JVM-тестов всех ОС.
Расширенные проверки и сборки всех трёх ОС [успешно выполнены в CI](https://github.com/GXUser7/yumi-desktop/actions/runs/43743630025).

Действующий VPN пользователя не переподключался. Интерактивная проверка TUN, физических сетей
и UAC/polkit/launchd остаётся ручным сценарием из MANUAL-TESTS.md; parser её не заменяет.
macOS требует стандартный hook `com.apple/*` в PF; нестандартный ruleset без него отклоняется явно.
