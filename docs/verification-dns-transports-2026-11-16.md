# Проверка DNS и транспортов — 2026-11-16

## Исправления

- На Windows DNS на адаптере TUN сам по себе не запрещал Windows обращаться к DNS других
  адаптеров. Добавлена отдельная динамическая WFP-сессия: TCP/UDP 53 разрешён к DNS туннеля,
  блокируется к другим адресам, включая DNS локального роутера. Защита включается до старта
  туннеля, действует без kill switch и при обходе LAN, повторно включается при возврате из
  VPN-off, снимается при отключении и завершении worker. Системный DNS-кеш очищается.
  Службе разрешён bootstrap адреса прокси; браузерный DoH подчиняется своей маршрутизации.
- DesktopModel сравнивает реальные TunnelOptions при изменении настроек. Изменения DNS,
  MTU, IPv6, обхода LAN, правил, kill switch, режима местоположения и физического адаптера
  применяются без зависимости от флага reconnect в конкретном обработчике интерфейса.
  Изменения во время подключения применяются после подтверждения worker; несколько изменений
  объединяются в последнюю сохранённую конфигурацию.
- При смене сервера старые VPN-потоки завершаются, включая длительные HTTP/2, DoH и mux.
  Прямые соединения исключённых приложений и VPN-off forwarder сохраняются. TUN, таймер
  и суммарные счётчики остаются. Приложения внутри VPN могут кратко переподключаться.
  Изменение DNS/MTU/маршрутизации по-прежнему требует пересоздания стека и может прервать
  также прямые соединения.

## Проверки

- JVM: первое подключение с DNS по умолчанию без нажатия «Сохранить»; автоматическое применение
  всех TunnelOptions; изменения во время подключения; освобождение kill switch после ошибки.
- Windows: `TestLiveWindowsDNSGuardBlocksOtherResolversAndRestoresOnClose` с явным opt-in
  `YUMI_VERIFY_DNS_GUARD=1` пройден с настоящими WFP-фильтрами. Внешний процесс PowerShell
  выполнял TCP/UDP DNS-запросы: DNS туннеля работал, другой DNS блокировался, после закрытия
  WFP-сессии ограничения исчезали. Установленная служба и сохранённые настройки не менялись.
- `TestEveryStreamTransportCarriesTraffic`: реальный обмен данными локальных VLESS-клиента
  и сервера на закреплённом Xray, с конфигурациями JVM-фабрики: TCP, WS, gRPC, HTTPUpgrade,
  XHTTP auto, packet-up, stream-up, stream-one. Без системного TUN или внешней сети.
- Матрица JVM → Go/Xray содержит 371 синтетическую конфигурацию протоколов, транспортов и TLS.
- Проверки liveOutbound: отмена старых VPN TCP/mux-потоков, сохранение прямых TCP/UDP-потоков,
  обработка неудачной замены и сохранение счётчиков.
- Полный запуск `:logic:test :platform:test :desktop:test :desktop:assemble` завершён успешно:
  461 JVM-тест пройден, 6 пропущены по условиям платформы/явного opt-in. `go test ./... -count=1`,
  `go vet ./...`, сборка Windows-службы и компиляция Linux-тестов также успешны.
  Windows race detector недоступен: найденный GCC из FPC не содержит `stddef.h` для runtime/cgo.
  Реальные голосовой сеанс Discord и матч Fortnite не запускались; сохранение прямых потоков
  проверено тестами ядра. Установленное приложение не заменялось, изменения не публиковались.
